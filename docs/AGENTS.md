# docs

## 用途

项目文档和设计方案存储目录，包含 API 文档、部署文档和详细的设计方案。

## 核心文件

当前目录无直接文件，所有文档按类型组织在子目录中。

## 子目录

| 目录 | 用途 |
|------|------|
| `plans/` | 设计方案文档 (详见 `plans/AGENTS.md`) |
| `api/` | API 文档（待补充） |
| `deployment/` | 部署文档（待补充） |

## AI Agent 工作指南

### 在此目录工作时

- 新增功能前应先在 `plans/` 目录创建设计文档
- 设计文档命名格式：`YYYY-MM-DD-功能名称.md`
- API 文档应与代码保持同步
- 部署文档应包含详细的环境配置和步骤说明

### 测试要求

- 文档无需测试，但应确保内容准确性
- 代码示例应该可以直接运行
- 配置示例应该完整可用

### 常见模式

- 使用 Markdown 格式编写文档
- 设计文档包含：背景、目标、架构设计、数据模型、API 设计、实现计划
- 使用图表辅助说明（Mermaid 或图片）
- 保持文档版本化，重大变更应更新文档

## 依赖关系

### 内部依赖

- 所有模块在开发前应参考此目录的设计文档
- `plans/` 中的设计文档指导 `backend/` 和 `frontend/` 的实现

### 外部依赖

无外部依赖

## 文档分类

- **设计方案**：架构设计、数据库设计、API 设计、业务流程设计
- **API 文档**：接口说明、请求响应示例、错误码说明
- **部署文档**：环境要求、安装步骤、配置说明、运维指南
