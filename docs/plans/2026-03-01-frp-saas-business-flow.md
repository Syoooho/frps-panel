# FRP SaaS平台 - 业务流程设计

## 1. 用户注册和激活流程

### 注册流程
```
1. 用户访问注册页面
2. 输入邮箱和密码
3. 系统验证邮箱格式和密码强度
4. 创建用户账号（is_active=False）
5. 返回注册成功，引导用户登录
```

### 激活流程
```
1. 用户登录后进入激活页面
2. 输入兑换码
3. 系统验证兑换码：
   - 是否存在
   - 是否已使用
   - 是否过期
4. 验证通过后：
   - 标记兑换码为已使用
   - 创建订阅记录
   - 分配端口配额
   - 设置到期时间
5. 用户可以开始创建隧道
```

## 2. 隧道创建流程

### TCP/UDP隧道
```
1. 用户在前端填写隧道配置
   - 隧道名称
   - 类型（tcp/udp）
   - 本地端口
   - 远程端口（可选，系统自动分配）

2. FastAPI后端验证：
   - 用户订阅是否有效
   - 配额是否充足（used_ports < port_quota）
   - 远程端口是否冲突
   - 隧道名称是否重复

3. 验证通过后：
   - 在tunnels表创建记录
   - 增加used_ports计数
   - 返回隧道配置信息

4. 用户使用frpc连接时：
   - Go插件接收frpc请求
   - 调用FastAPI验证接口
   - FastAPI验证用户token和配额
   - 返回允许/拒绝结果
```

### HTTP/HTTPS隧道
```
1. 用户填写配置
   - 隧道名称
   - 类型（http/https）
   - 本地端口
   - 自定义域名或子域名

2. FastAPI后端验证：
   - 订阅和配额检查
   - 域名是否冲突
   - 子域名格式验证

3. HTTP/HTTPS隧道共享80/443端口
   - 不占用端口配额（可选策略）
   - 或按域名数量计算配额

4. 创建隧道记录并返回配置
```

## 3. 配额控制逻辑

### 配额计算规则
```
- TCP/UDP类型：每个隧道占用1个端口配额
- HTTP/HTTPS类型：
  方案A：不占用配额（推荐）
  方案B：每个域名占用1个配额
- STCP/SUDP类型：不占用配额
```

### 配额检查时机
```
1. 创建隧道时：检查 used_ports < port_quota
2. frpc连接时：验证用户订阅状态
3. 订阅到期时：
   - 禁止创建新隧道
   - 现有隧道保留24小时宽限期
   - 宽限期后自动下线
```

### 配额释放
```
1. 用户删除隧道时：
   - 删除tunnels记录
   - 减少used_ports计数
   - 通知Go插件断开连接

2. 订阅到期后：
   - 不自动删除隧道记录
   - 仅标记为不可用
   - 用户续费后自动恢复
```

## 4. 管理员生成兑换码流程

### 批量生成
```
1. 管理员登录后台
2. 选择套餐类型（monthly/yearly）
3. 输入生成数量
4. 设置兑换码有效期（可选）
5. 系统批量生成唯一兑换码：
   - 格式：XXXX-XXXX-XXXX-XXXX
   - 使用UUID或随机字符串
   - 确保唯一性
6. 保存到activation_codes表
7. 可导出为CSV或复制到剪贴板
8. 线下分发给用户
```

### 兑换码管理
```
1. 查看兑换码列表
   - 筛选：已使用/未使用
   - 搜索：按兑换码查询
   - 显示：使用者、使用时间

2. 删除兑换码
   - 仅可删除未使用的兑换码
   - 已使用的兑换码不可删除（保留记录）
```

## 5. Go插件与FastAPI集成

### 现有Go插件改造
```
原有逻辑：
- HandleLogin: 验证用户token
- HandleNewProxy: 验证端口/域名限制
- HandlePing: 心跳检测

改造后：
1. 接收frpc请求
2. 提取user和token
3. 调用FastAPI验证接口：
   POST /api/v1/frp/validate
   {
     "user": "user@example.com",
     "token": "user_token"
   }
4. FastAPI返回验证结果：
   {
     "valid": true,
     "user_id": 1,
     "port_quota": 10,
     "used_ports": 3
   }
5. Go插件根据结果允许/拒绝连接
```

### 隧道状态同步
```
1. 隧道上线时：
   - Go插件调用 POST /api/v1/frp/tunnel/register
   - 更新tunnels表status为online
   - 记录last_active时间

2. 隧道下线时：
   - Go插件调用 POST /api/v1/frp/tunnel/unregister
   - 更新status为offline

3. 心跳检测：
   - 定期更新last_active时间
   - 超时未心跳则标记为offline
```

## 6. 订阅到期处理

### 到期检测
```
1. 定时任务（每小时执行）：
   - 查询expire_date < now()的订阅
   - 更新status为expired

2. 到期前提醒：
   - 提前7天发送邮件提醒
   - 提前1天再次提醒
```

### 宽限期处理
```
1. 订阅到期后24小时内：
   - 用户可查看隧道但不能创建新隧道
   - 现有隧道继续运行
   - 前端显示续费提示

2. 宽限期结束后：
   - 所有隧道自动下线
   - 用户无法连接frpc
   - 隧道记录保留（不删除）
```

### 续费流程
```
1. 用户使用新兑换码激活
2. 系统检测到已有订阅：
   - 如果未过期：延长到期时间
   - 如果已过期：创建新订阅
3. 恢复隧道可用状态
4. 用户可继续使用
```

## 7. 用户管理流程

### 管理员操作
```
1. 查看用户列表
   - 显示邮箱、订阅状态、隧道数量
   - 搜索和筛选功能

2. 禁用用户
   - 设置is_active=False
   - 断开所有隧道连接
   - 用户无法登录

3. 启用用户
   - 设置is_active=True
   - 用户可正常登录

4. 删除用户
   - 删除用户记录
   - 级联删除订阅和隧道
   - 不可恢复操作
```
